# قائمة قبول المستخدم — PipeERP Web

تُنفذ هذه القائمة على نسخة مرشحة للإطلاق ببيانات اختبار ممثلة، مرة من كمبيوتر ومرة من
هاتف. يسجل لكل حالة: المنفذ، التاريخ، النتيجة، ورقم البلاغ إن فشلت.

## الدخول والصلاحيات

- [ ] دخول المدير، تغيير كلمة المرور المؤقتة، الخروج، وانتهاء الجلسة.
- [ ] مستخدم قراءة فقط لا يستطيع إنشاء أو اعتماد أو عكس أي مستند.
- [ ] تبويبات المبيعات بالقطعة والوزن والحسابات والتصنيع مستقلة حسب الصلاحية.
- [ ] محاولة رابط API مباشر دون صلاحية تُرفض ويظهر أثرها في سجل التدقيق.

## البيانات الأساسية والمخزون

- [ ] إنشاء وتعديل منتج وعميل ومورد ووحدة مع منع التكرار والتعارض المتزامن.
- [ ] استلام وصرف وتسوية وتحويل مخزني، مع مطابقة الكمية والوزن وكارت الصنف.
- [ ] محاولة صرف أعلى من الرصيد تُرفض دون حركة جزئية.
- [ ] عكس حركة يعيد الرصيد والتكلفة ويحفظ السجل التاريخي.

## المشتريات والمبيعات والحسابات

- [ ] أمر شراء متعدد البنود، اعتماد، استلام جزئي ثم كامل، فاقد، وفاتورة مورد.
- [ ] أمر بيع قطعة وتسليم وفاتورة، ثم بيع وزن وكارتة وصافي وزن وفاتورة.
- [ ] تحصيل جزئي/كامل وسداد مورد وتخصيص، مع مطابقة المتبقي وكشف الحساب.
- [ ] تحويل خزينة وتسوية وعكس دون إنشاء رصيد جزئي أو مكرر.
- [ ] مرتجع مبيعات ومشتريات واسترداد مبلغ وعكس، مع مطابقة المخزون والحساب.

## التصنيع — دون تغيير المنطق المثبت

- [ ] وصفة ومخرجات، تخطيط وإعادة تخطيط وكسر اختياري مطابق للمرجع.
- [ ] بدء أمر، صرف FIFO، خلطات إضافية، ورد خامات غير مستخدمة.
- [ ] إكمال بوزن فعلي وهالك وخلطة معدلة، مع مطابقة توزيع التكلفة.
- [ ] خمس محاولات متزامنة لا تصرف المخزون نفسه مرتين.

## التقارير والطباعة

- [ ] التقارير الستة تطابق الأوامر والفواتير والأرصدة والحركات وطبقات FIFO.
- [ ] تصدير XLSX عربي مع صف عنوان وفلتر وتجميد الرأس.
- [ ] فاتورة قطعة ووزن وعرض سعر A4 صحيحة، وكل ستة بنود في صفحة مرقمة.
- [ ] كشف حساب مختصر وتفصيلي، وإظهار المسودات دون أثر على الرصيد، وPDF/XLSX.

## الموبايل والأداء

- [ ] القائمة المتحركة تعمل، ولا يوجد قسم بلا وسيلة تنقل على عرض 360px.
- [ ] النماذج والأزرار قابلة للمس، والجداول تمرر أفقيًا دون قطع الإجراءات.
- [ ] خمس جلسات تعمل معًا على الدورات الحرجة دون خطأ أو بيع/صرف مزدوج.
- [ ] الصفحات الأساسية تستجيب ضمن هدف القبول المتفق عليه على شبكة العميل.

## التشغيل والاستعادة

- [ ] HTTPS صالح ولا يمكن فتح التطبيق عبر HTTP دون تحويل آمن.
- [ ] `/health` و`/health/ready` سليمان والمراقبة تنبه عند فشلهما.
- [ ] إنشاء نسخة مشفرة، التحقق من SHA-256، واستعادتها إلى قاعدة منفصلة.
- [ ] تنفيذ rollback التجريبي، ثم توثيق قرار Go/No-Go وتوقيع مالك النظام.
