# المعمارية المستهدفة

## النمط

تطبيق واحد منظم إلى وحدات أعمال واضحة، وليس Microservices. حجم الاستخدام المتوقع لا يبرر تعقيد الخدمات المنفصلة، بينما الفصل الداخلي يسمح باستخراج خدمة مستقبلًا إذا ظهرت حاجة حقيقية.

كل وحدة تتبع الاتجاه التالي:

```text
API -> Application service -> Domain rules -> Repository -> PostgreSQL
```

لا تستدعي الواجهة قاعدة البيانات، ولا تحتوي مسارات API على معادلات مالية أو منطق تصنيع مباشر.

## الوحدات الأساسية

1. الهوية والصلاحيات وسجل التدقيق.
2. البيانات الأساسية.
3. المخزون والتشغيلات وFIFO وطبقات الوزن.
4. المشتريات.
5. المبيعات بالقطعة والوزن.
6. الخزانة وحسابات الشركاء.
7. التصنيع.
8. المرتجعات.
9. التقارير ومستندات A4.

## قرارات ثابتة

- `NUMERIC` في PostgreSQL و`Decimal` في Python للأموال والكميات والأوزان.
- ترقيم المستندات من جدول تسلسلات مقفول داخل المعاملة، وليس `COUNT + 1`.
- حجز طبقات FIFO باستخدام قفل صفوف PostgreSQL داخل معاملة قصيرة.
- أوامر التغيير الحساسة تدعم مفتاح منع التكرار.
- كل مستند تشغيلي يملك حالة واضحة وانتقالات مسموحًا بها فقط.
- سجل التدقيق يحفظ الفاعل والوقت ونوع العملية والمرجع والفرق قبل/بعد.

## الواجهة

- عربية RTL أولًا، ومتجاوبة من الهاتف إلى شاشة اللابتوب والشاشات الكبيرة، مع قائمة
  تنقل هاتفية لا تعرض إلا الوحدات التي تسمح بها صلاحيات المستخدم.
- نظام تصميم داخلي موحد للألوان والمسافات والخطوط والجداول والنماذج.
- حالات تحميل وفراغ وخطأ ونجاح واضحة.
- التنقل والوصول يعتمد على صلاحيات المستخدم الفعلية.
- مستندات A4 تستخدم قوالب طباعة مستقلة عن تخطيط الشاشات.
