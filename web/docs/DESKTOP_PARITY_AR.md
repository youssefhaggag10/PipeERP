## المرجع والقاعدة

- مرجع السلوك الوحيد: فرع الديسكتوب `main` عند الكوميت `70850aa`.
- فرع التنفيذ: `web-rebuild`.
- تمت المقارنة على مستوى الإجراء والشاشة والتحقق والنتيجة وأثر المخزون والحسابات والحسابات الرقمية.
- الاستثناءات الوظيفية المعتمدة: الإبقاء على عمليات العكس الموجودة، والإبقاء على لوحة التشغيل المحسّنة، ووضع شعار المنشأة ثابتًا في الهيدر بدل العلامة المائية داخل الصفحات، بطلب صريح من المالك.
- حماية التزامن ومنع تكرار الطلب وسجل التدقيق وحماية الجلسات اختلافات تقنية لازمة للويب وليست خطوات عمل جديدة.

## السلوك النهائي للمستخدم

| الوحدة | السلوك المطابق |
| --- | --- |
| الرئيسية | استثناء معتمد: مؤشرات اليوم، حركة التشغيل، التنبيهات، والإجراءات السريعة حسب الصلاحيات. |
| المستخدمون | يمكن إنشاء مستخدم بلا صلاحيات، ولا توجد خطوة إجبارية لتغيير كلمة المرور عند أول دخول. |
| العملاء والموردون | سجل منفصل لكل نوع، وحقول الكود والاسم والهاتف والعنوان، مع عرض الحركات المرتبطة داخل شاشة الطرف. |
| الأصناف | نفس الحقول الأساسية، مع فرض تتبع الدفعات داخليًا وعدم إظهار التصنيفات أو قرار تتبع الدفعات للمستخدم. |
| المخزن | مخزن وحيد ثابت `MAIN / المصنع`. لا إنشاء أو تعديل مخازن إضافية ولا تحويل بين مخازن. |
| رصيد المخزون | تسوية موجبة أو سالبة، والملاحظات اختيارية، مع منع الرصيد السالب. |
| أرصدة الدفعات | أرصدة وتكاليف FIFO الفعلية في مخزن المصنع. |
| كارت الصنف | صف واحد لكل حركة مثل الديسكتوب، مع تجميع تخصيصات FIFO الداخلية في العرض وإظهار التاريخ والدفعة والداخل والخارج والتكلفة والمرجع والطرف. |
| المشتريات | حفظ أمر مسودة ثم استلام كامل مباشر. الاستلام يضيف المخزون وينشئ فاتورة المورد في نفس المعاملة. لا اعتماد مستقل، لا استلام جزئي، لا دفعة من شاشة الأمر، ولا اختيار كمية/وزن. الكمية تحمل وحدة القياس؛ مثال `1037.5 كجم`. |
| المبيعات | حفظ أمر مسودة ثم تسليم مباشر، مع خصم FIFO وإنشاء فاتورة العميل في نفس العملية. الدفع يتم من الحسابات. البيع بالوزن والكارتة مستمران بنفس منطق الديسكتوب. |
| الحسابات | تحصيل العميل يمكن توزيعه على فواتير؛ سداد المورد يرتبط بأمر شراء أو يكون مقدمًا ولا يوزع على عدة فواتير. كشف الحساب المعتاد للعملاء فقط. لا إنشاء تسوية مستقلة لحساب عميل. |
| التصنيع | قبل بدء الأمر تظهر شاشة توافر الخامات: المطلوب والمتاح وما سيصرف والعجز. عجز الخامة الأساسية يمنع البدء، وعجز الكسر يسمح بإعادة التخطيط مثل الديسكتوب، ثم يعاد التحقق داخل معاملة الصرف. |
| CRM | مزامنة العملاء الحاليين إلى CRM دون تكرار، وجدولة الأنشطة لمدير النظام فقط، مع بقية دورة العملاء المحتملين والمراحل والتقارير. |
| التقارير والطباعة | نفس التقارير الستة، مع طباعة A4 وتخطيط حراري 80mm لمستندات البيع. |

## عمليات العكس المحتفظ بها عمدًا

- عكس تسليم/فاتورة البيع إذا لم تمنعه حركة مالية أو مخزنية لاحقة.
- عكس فاتورة المورد ثم استلام الشراء بالترتيب الآمن.
- عكس التحصيلات والمدفوعات والحركات المالية المدعومة.
- عكس المرتجعات والاستردادات والحركات المخزنية المدعومة.

هذه العمليات ليست مطابقة للديسكتوب لكنها الاستثناء الصريح المعتمد. جميعها تحتفظ بسبب العكس ومفتاح منع التكرار وسجل التدقيق وحواجز سلامة الأرصدة.

## لوحة التشغيل المحتفظ بها عمدًا

لوحة التشغيل المحسّنة استثناء صريح اعتمده المالك، وتحتوي على مؤشرات اليوم، آخر حركات البيع والشراء والتصنيع، التنبيهات، والإجراءات السريعة المرتبطة بصلاحيات المستخدم. لا تُستبدل بملخص مؤشرات المخزون الخاص بالديسكتوب في مراجعات المطابقة اللاحقة.

## شعار الهيدر

صورة الشعار المختارة سابقًا من إعدادات العلامة المائية تُنقل تلقائيًا إلى الهيدر، وتظهر ثابتة بجوار اسم المستخدم على جميع الشاشات. أُلغي عرض الشعار كعلامة مائية في منتصف المحتوى، ويظل شعار PipeERP الافتراضي ظاهرًا إذا لم تُرفع صورة مخصصة.

## فرق متبقٍ يحتاج موافقة

`SRET-3`: الديسكتوب يعيد تكلفة مرتجع المبيعات بمتوسط التكلفة التاريخية الخارجة للصنف/الأمر، بينما الويب يعيد التكلفة الدقيقة لسطر التسليم. تغيير ذلك سيغير تقييم المخزون وFIFO المستقبلي؛ لذلك لم يُغير دون موافقة صريحة على أثر التقييم. لا توجد فروق وظيفية معلقة أخرى معروفة ضمن التدقيق الحالي.

## اختلافات تشغيلية لا تضيف قرار عمل

- اختيار الطابعة يتم من نافذة طباعة المتصفح.
- استرجاع قاعدة PostgreSQL الحية يتم بأداة التشغيل الآمنة، وليس من طلب داخل متصفح متعدد المستخدمين.
- مخطط قاعدة البيانات يحتفظ ببعض الأعمدة والحالات القديمة لقراءة السجل وعكس الحركات السابقة، لكنها غير متاحة لإنشاء سير عمل جديد من الواجهة أو الـAPI العام.

## بيانات الديمو

من داخل `web`:

```bash
python3 ops/demo_seed.py --yes
```

تطلب الأداة كلمة مرور مدير النظام تفاعليًا، وتجهز بيانات مترابطة على مخزن المصنع دون حذف البيانات الحالية أو مضاعفة المستندات عند إعادة التشغيل.

## التشغيل

```bash
git pull --ff-only origin web-rebuild
cd web
docker compose up --build
```

ثم افتح `http://localhost:5173`.
