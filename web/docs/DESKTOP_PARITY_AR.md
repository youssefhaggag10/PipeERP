# توثيق مطابقة PipeERP Web مع نسخة الديسكتوب

آخر تحديث: 24 أغسطس 2026

## مرجع المراجعة

- نسخة الديسكتوب المرجعية: فرع `main` عند الكوميت `70850aa`.
- نسخة الويب الجاري تسليمها: فرع `web-rebuild`.
- قاعدة المراجعة: السلوك الفعلي في صفحات الديسكتوب ومستودعاته وخدماته، وليس شكل الصور فقط.
- الاستثناء الوحيد الذي وافق عليه صاحب المشروع: الاحتفاظ بلوحة تشغيل الويب المحسّنة التي تعرض مبيعات اليوم، أوامر التشغيل، تنبيهات المخزون، الوزن المباع، آخر الحركات والإجراءات السريعة.

## حالة الوحدات والمنطق المطابق

| الوحدة | ما تمت مطابقته |
| --- | --- |
| الأصناف | نفس بيانات الصنف الأساسية، الوحدات الفعلية، حد المخزون والوزن القياسي، مع التعديل والحذف. أُزيلت إدارة التصنيفات وخيارات تتبع الدفعات والنشاط من الواجهة لأنها لم تكن ظاهرة في شاشة الديسكتوب النهائية. |
| العملاء والموردون | صفحتان منفصلتان بنفس منطق الديسكتوب، مع البحث والإضافة والتعديل. |
| إعداد المخزن | يعرض مخزن المصنع فقط في جدول الكود والاسم، ولا توجد شاشة ويب لإضافة فروع مخازن. |
| رصيد المخزون | رصيد ناتج من الحركات الفعلية، وتسوية موجبة أو سالبة للصنف المحدد. رقم الدفعة في الإضافة يُنشأ تلقائيًا. البيانات الظاهرة تخص مخزن المصنع. |
| أرصدة الدفعات | الأعمدة المطابقة: الكود، الصنف، المخزن، رقم الدفعة، تاريخ الاستلام، المستلم، المصروف، المتبقي، متوسط التكلفة، القيمة. الصرف محسوب بنظام FIFO. |
| كارت الصنف | الأعمدة المطابقة: التاريخ، الكود، الصنف، المخزن، الدفعة، داخل، خارج، التكلفة، المرجع، الطرف. المراجع والأطراف تُقرأ من أوامر البيع والشراء والتصنيع والمرتجعات والتسويات. |
| المشتريات | أمر الشراء يبدأ مسودة. زر الاستلام ينفذ الاعتماد الداخلي ثم الاستلام مرة واحدة، يضيف صافي الكمية للمخزون، ويُنشئ فاتورة المورد تلقائيًا. لا توجد دفعة مقدمة أو استلام جزئي أو اعتماد منفصل في الواجهة النهائية. |
| فقد الشراء | `الصافي = إجمالي الكمية - الفقد`. مستحق المورد لا يشمل التجهيز الداخلي. تكلفة المخزون تحمل سعر المورد والتجهيز الداخلي على صافي الكمية: `(الإجمالي × (سعر المورد + التجهيز الداخلي)) ÷ الصافي`. |
| المبيعات العادية | أمر بيع مسودة ثم تسليم مباشر. التسليم يخصم FIFO من المخزون ويُنشئ فاتورة العميل. لا توجد دفعة مقدمة أو إلغاء/عكس ظاهر في الشاشة. |
| البيع بالوزن / الكارتة | داخل قائمة المبيعات، ويحافظ على الكارتة وبيانات السيارة والوزن القائم والفارغ والصافي وسعر الكيلو والتسليم والفاتورة. |
| الحسابات | ملخص المبيعات والمشتريات والتحصيلات والمدفوعات والمديونيات والدفعات المقدمة، ثم التحصيل والسداد، الخزائن والبنوك، أرصدة العملاء والموردين وكشوف الحساب، فواتير المبيعات، فواتير المشتريات، والمرتجعات والاستردادات. التحويل المباشر بين الحسابات مخفي مثل نسخة الديسكتوب النهائية. |
| فواتير الحسابات | تعرض رقم الفاتورة والأمر والوقت والطرف والهاتف والإجمالي الأصلي والمرتجع والصافي والمدفوع وطريقة الدفع والمتبقي وحالات الفاتورة والتسليم/المرتجع والدفع. يمكن بدء التحصيل/السداد أو المرتجع من الفاتورة نفسها. |
| التصنيع | أوامر التصنيع وتعريف الخلطات، الإنتاج المطلوب، الخامات والكسر، بدء الأمر، إعادة التخطيط، الإلغاء ورد الخامات، وإكمال الإنتاج بالكميات السليمة والهالك والتعديلات وتكلفة الناتج. أُزيلت مؤشرات الويب الإضافية من أعلى الصفحة. |
| CRM | التبويبات المطابقة: لوحة المتابعة، العملاء المحتملون، الأنشطة، مراحل المبيعات، تقارير CRM. يشمل الجدولة والمتابعة والتحويل إلى عميل. |
| التقارير | نفس الأنواع الستة: المبيعات، المشتريات، أرصدة العملاء، أرصدة الموردين، التحصيل والسداد، تقييم المخزون. طباعة مستندات A4 موجودة في مركز الطباعة. |
| الإعدادات | الطباعة، العلامة المائية، المظهر، النسخ الاحتياطي، المستخدمون والصلاحيات، وتصفير الحركات. إدارة المستخدمين أصبحت داخل الإعدادات بنفس جدول ونموذج الديسكتوب، وليست شاشة إدارة ويب إضافية في مسار الاستخدام الطبيعي. |
| بيانات الطباعة | اسم المنشأة، العنوان، وقائمة مرتبة لأرقام الشركة والمبيعات؛ رقم في كل سطر والرقم الأول هو الرئيسي. |
| تصفير الحركات | يحتاج عبارة `تصفير النظام` وكلمة مرور مدير النظام. يحذف المستندات والحركات ويحافظ على البيانات الأساسية والمستخدمين والإعدادات والأرصدة الافتتاحية. |

## الاختلافات المتعمدة أو المرتبطة ببيئة الويب

1. لوحة التشغيل المحسّنة زيادة عن الديسكتوب، وتم الاحتفاظ بها بطلب صريح من صاحب المشروع.
2. اختيار الطابعة يتم من نافذة طباعة المتصفح؛ موقع الويب لا يستطيع فرض طابعة نظام افتراضية مثل برنامج الديسكتوب.
3. إنشاء النسخة الاحتياطية اليدوية متاح من الإعدادات كملف PostgreSQL كامل. استرجاع قاعدة الإنتاج لا يتم من جلسة متصفح نشطة لأن الويب متعدد المستخدمين؛ يتم من إجراء التشغيل الآمن `web/ops/restore.sh` على قاعدة استعادة محددة. خدمة النسخ المشفر والاحتفاظ الدوري موجودة في إعداد الإنتاج.
4. نموذج الصلاحيات الداخلي في الويب يعتمد أدوارًا تُفرض من الخادم، لكن شاشة الاستخدام العادية تعرض نفس جدول المستخدم والدور والحالة المطلوب في الديسكتوب.

## بيانات الديمو

أداة الديمو تنشئ بيانات قابلة للاختبار بدون مضاعفة نفس المستندات عند تشغيلها مرة أخرى، وتشمل:

- أصناف خامات ومنتج تام وهالك وقطعة غيار وخدمة.
- عميلين وموردًا وحساب خزينة وحساب بنك.
- أرصدة ودفعات على مخزن المصنع فقط.
- أمر شراء مستلم وفاتورة مورد.
- بيع عادي وبيع بالوزن وفواتير وعرض سعر وأمر مسودة.
- خلطة وأمر تصنيع جارٍ.
- عميل محتمل ونشاط CRM.
- مرتجع بيع جزئي وتحصيل وسداد وأرصدة افتتاحية وتسويات.

التشغيل من مجلد `web`:

```bash
export PIPEERP_DEMO_ADMIN_PASSWORD='كلمة-مرور-مدير-النظام'
python3 ops/demo_seed.py --username admin --yes
```

## تشغيل الويب محليًا

من مجلد المشروع:

```bash
cd web
docker compose up --build
```

ثم افتح `http://localhost:5173`.

لجلب آخر تحديثات الفرع الحالي قبل التشغيل:

```bash
git pull --ff-only origin web-rebuild
```

## التحقق المنفذ

- ترقية مخطط PostgreSQL من أول migration حتى آخر migration.
- اختبارات backend كاملة.
- فحص Ruff وMypy.
- اختبارات frontend كاملة.
- فحص ESLint وبناء نسخة الإنتاج.
- اختبار فعلي بالمتصفح على مقاس الديسكتوب والموبايل.
- اختبار المبيعات والمشتريات على الموبايل، بما في ذلك تدوير الشاشة أفقيًا ثم رأسيًا والتنقل لشاشة أخرى والعودة.
- اختبار كارت الصنف وأرصدة الدفعات وأعمدتهما.
- اختبار فواتير المبيعات والمشتريات داخل الحسابات.
- اختبار تبويبات CRM والتصنيع والتقارير والإعدادات وإدارة المستخدمين.
