# عقد المرحلة 11 — التقوية والقبول والنشر

هذه المرحلة لا تغيّر منطق الديسكتوب أو معادلات المخزون والتصنيع والتكلفة. هدفها تثبيت
تشغيل نسخة الويب بأمان، وإثبات إمكانية النسخ والاستعادة، ثم قبول المستخدم والنشر.

## حدود التنفيذ

- PostgreSQL 17 هو مصدر الحقيقة الوحيد، وAlembic هو المسار الوحيد لتغيير المخطط.
- لا تُخزن أسرار إنتاجية في Git أو `.env.production`؛ تُركب كملفات Docker secrets.
- لا يُنشر PostgreSQL أو Backend أو Frontend مباشرة للإنترنت؛ المنفذان العامان هما
  `80/443` عند بوابة TLS فقط.
- لا يبدأ نشر VPS أو تغيير DNS دون بيانات الخادم والنطاق ونافذة نشر معتمدة.
- الطباعة الحرارية خارج النطاق، ولا تعاد إضافتها أثناء التقوية.

## ضوابط الإنتاج

1. `APP_ENV=production` يغلق توثيق API، يفرض Secure cookies، ويرفض CORS غير HTTPS
   وقيم الأسرار الافتراضية واتصال قاعدة غير PostgreSQL/psycopg.
2. حاويات التطبيق تعمل بنظام ملفات للقراءة فقط، `no-new-privileges`، وحدود ذاكرة وعمليات،
   ولا تحصل إلا على الأسرار التي تحتاجها.
3. Caddy ينهي TLS تلقائيًا ويضيف HSTS وCSP وسياسات منع الإطارات والمحتوى غير المصرح.
4. `/health` للحياة، و`/health/ready` يختبر اتصال قاعدة البيانات قبل تمرير التشغيل.
5. سجلات HTTP بصيغة JSON تشمل request ID والمسار والحالة والمدة، ولا تسجل query string
   أو body أو cookies أو أسرار.
6. سجلات Docker تدور عند 10MB وبحد خمسة ملفات لكل حاوية.
7. فحص readiness خارجي يعيد exit code غير صفري ويرسل webhook اختياريًا عند الفشل، واختبار
   حمل موحد يقيس خمس جلسات مصادق عليها ويُفشل القبول عند أخطاء HTTP أو تجاوز p95.

## عقد النسخ والاستعادة

- النسخة من `pg_dump` بصيغة custom، وتُفحص بـ`pg_restore --list` قبل اعتمادها.
- الملف يُشفّر AES-256-CBC مع PBKDF2 بمفتاح مستقل، ويصدر معه SHA-256.
- سياسة الاحتفاظ الافتراضية 14 يومًا ولا تحذف إلا ملفات `pipeerp-*.dump.enc` داخل مجلد
  النسخ المحدد بعد رفض `/` والقيمة الفارغة.
- الاستعادة ترفض العمل دون checksum ومفتاح التشفير، ودون تأكيد صريح واسم قاعدة هدف مطابق.
- اختبار الاستعادة يستخدم قاعدة منفصلة، وينجح فقط إذا أعاد المخطط وجدول Alembic.
- النسخ لا تُعتبر صالحة لمجرد إنشائها؛ يلزم اختبار استعادة دوري موثق.

## شرط الإغلاق

لا تُغلق المرحلة حتى تنجح: اختبارات النظام كاملة، Compose وCaddy، نسخة مشفرة واستعادة
فعلية على PostgreSQL، سيناريوهات UAT على كمبيوتر وموبايل، اختبار أداء ممثل لخمس جلسات،
فحص أمان وتبعيات، نشر TLS، وrollback تجريبي أو موثق قابل للتنفيذ.
